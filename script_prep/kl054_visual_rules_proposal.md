## 3. `kl_dialogue.py check` の新しい規則（実装済み。visuals がある回だけ働く）

- visuals は1つ以上の要素のリスト。teaser には使えない。visuals のあるシーンにシーン直下の `source_card`・`chart` を置かない
- `from_line`: 1〜行数の整数、最初は 1、昇順・重複なし
- 種類はちょうど1つ。`scene_image` はシーンに画像があること。`image_asset` は `assets/{名前}.png` があること
- `photos/` の素材は `real_photo: true` が必須。出所の記録（`.json`）があり、Commons はライセンスが許可範囲・概要欄に写真の名前がある、取り込み（import）は出所・クレジット・利用条件・確認の印があり、概要欄にクレジットがある
- `source_card`・`chart` は `reference_index` が references にあること、種類・資料名・行数・字数（シーン直下のカードと同じ基準）
- `recap_card`・`step_card` はタイトル1〜24字、1〜5行、1行26字
- カードの静止画（`kl_dialogue.py cards`）があること。`bg_asset` の画像があり、写真なら出所の記録とクレジット
- 音声の後（`t0` がある）は、1枚の画像が3秒以上出ること

**追加を勧める検査（未実装・決まってから入れる）:**
- 構成 v4 の setup・verdict・closing で、カフェの固定背景（`base_cafe*`）だけが40秒を超えて続いたら ⚠（不合格にはしない）。決まりが 1-1 のとおりになったら入れる
- verdict で、`verdict_from_line` 以降にまとめのカードが出ていたら ⚠（札とカードが重なる）

## 4. 写真の優先順位と記録（案。手順書 (7) の順番を写真全体に広げる）

1. Commons などの自由ライセンス（PD・CC0・CC BY・CC BY-SA）。`fetch`
2. 公的機関の画像（NIH・NCI・NIAID・CDC 等。多くは米国の政府著作物でパブリックドメイン。ページごとの条件を `import --kind government` で記録）
3. 会社のプレス向け配布素材（`import --kind press`。条件・URL を記録）
4. 報道記事の写真（手順書 (7) で条件付きで認められているが、記事の写真の著作権は報道機関・撮影者にあり、プレス素材のような利用許諾が無いことが多い。**映像担当としては、報道記事の写真は使わない運用を勧める**。使うなら、記事ごとの利用許諾を確かめた記録を必須にする）
5. 見つからなければ、コードで描くカード・グラフ（費用ゼロ）、それでも足りなければ AI のイラスト

## 5. 画面の型（お題と予想・判定・締め。kl054 の創薬の回での例）

- **お題と予想（約140秒）:** カフェ（頭の自己紹介の7秒＋お題の1行目）→ データセンターの写真（「AIの会社が」）→ 実験室のロボットアームの写真（「薬の開発を始めた」）→ 発表の資料カード（提携6社の名前を箇条書き。原文の要約）→ T細胞の電子顕微鏡写真（大輔の予想「次は〜」）→ 抗体の分子模型（沙織の予想「確かめたいのは〜」）。6枚、1枚20〜25秒
- **判定（約175秒）:** ふりかえりカード（論点1〜3の手応えを1行ずつ。台詞の「論点1は〜」に合わせて `motion_cues.items` で1行ずつ出す）→ 判定の札の行から薬局の棚の写真（札が主役）→ 今日の一歩のカード（ピペットの写真をぼかして敷く）。1枚40〜60秒になるので、ふりかえりは1論点1枚に分けてもよい
- **締め（24秒）:** バイオリアクターの写真（ゆっくり寄る）→ 最後の固定 CTA の行からカフェ（ホームに戻る）
