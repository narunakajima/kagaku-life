# 台本の書き手への共通規則（毎回、全文をプロンプトに含める）

2026-10-19 作成。kl046（マスク氏「2036年にお金は意味を失う」）で、Opus が書いて別の Opus がレビューし、機械チェックとファクトチェックを通した台本でも、制作者から「意味がわからない」「主語がない」「モデルて何？」「たとえがわからない」という指摘が1つずつ10回近く続いた。原因は、書き手もレビュー役も資料を読み込んだ状態で台本を読んでおり、**初めて聞く人がどこで詰まるかを誰も確かめていなかった**ことにある。この規則は、そのとき出た指摘（制作者の10件、初見レビューの35件）を一般化したもの。`kl-new.md` STEP2 の「生成ルール」と一緒に、書き手（Opus サブエージェント）へのプロンプトに全文を入れる。

## 0. 前提
- **伝わることが最優先。尺・字数・シーン数は制約にしない。** 説明が要るなら行や場面を足す。冗長なら削る。台詞の規則（同じ人は3行まで、一人が7割まで）が説明の邪魔になったら、相づち・聞き返し・言い直しを挟んで収める（相づちは、聞き手の理解を言い直す役目にすると、かえって分かりやすくなる）。
- **想定する視聴者（2026-10-25 改訂、CLAUDE.md「想定する視聴者」）:** AIや新しい技術に興味がある50〜60代。経営者・自営業・商売をしている人が多く、会社勤めの人も、退職した人もいる。「自分の店・会社で使えるか」を気にする。経済学も統計も論文も知らない。有名人の名前は知っているが、今回の発言は知らない。動画は一度だけ、耳で聞く（画面の資料カード・図の文字は見える）。

## 1. 書く前の準備（台詞を書く前に、リポジトリの `script_prep/kl{NNN}.md` に書いて保存する。git で追跡する）
1. **論点ごとの「中学生に3文で説明すると」メモ。** 3文で平易に言えない仕組みは、まだ台詞にしない（下の規則 g）。
2. **たとえ話の対応表。** 使うたとえごとに「たとえの要素 → 原典の要素」を表にし、原典の該当箇所（文・ページ）と照合する。合わない要素があるたとえは使わない。
3. **「初めて説明が要る考え方」の数。** 視聴者がこの回で初めて聞く考え方（例: AIの伸びの測り方、生産性、お金の入り口、自動化と賃金、資本、財源、所得の実験）を数える。**5つを超えたら**、資料（論点）を減らし、説明専用の場面を作る（たとえ1つと図1枚で、その場面に台本の3割を割いてよい）。
4. **キーワードの一覧。** この回だけの言い方（例:「爆発」「入り口」）と、その定義の一文。
5. **お題の主張の正確な形。** 誰が、いつ、何を、どの範囲で言ったか（発表の言い方への札 `claim_verdict` はこれに対して付ける。規則 j）。
6. **論点ごとの「壁 → 越え方 → 残った手応え」（構成 v4、2026-10-26〜）。** 論点ごとに、沙織が出す壁、資料から見つかる越え方（条件・使い方・待てば変わること）、論点の最後に言う「残った手応え」（資料で確かめられた、前向きに使える事実）を1行ずつ書く。手応えが資料に見つからない論点は、論点ごと入れ替える。あわせて、沙織の「本物なら私はこれに使いたい」と、大輔の側を支える資料で沙織が認める論点を決める。

## 2. 台詞の規則（それぞれ、kl046 で実際に起きた失敗を添える）
- **(a) 伝わることを先に、短さは後に。** 1行を短くするために主語や前提を削らない。
  - 失敗: 1行を短く切った結果、S13 の説明が「主語がほとんどないので全くわからない」と言われた。
- **(b) キーワードは最初に一度定義する。** その回だけの言い方（比喩語）を使うなら、初出の行で「この回では、これを〇〇と呼ぶ」と言う。
  - 失敗: 「爆発」を20回近く使いながら、何のことかを一度も言わなかった。サムネイルの「何が爆発するのか分からない」という指摘もここから来た。
- **(c) 初出の専門用語・略語・固有名・数字は、その行か次の行で日常の言葉に言い換える。** 「つまり」「っていうのは」「〜のこと」「〜という研究機関」などで。英字の名前は読み方も決める（台詞はカタカナ、字幕は `display` で英字）。
  - 失敗: 「モデルは決めてない」に「モデルて何？」と言われた。「生産性」「資本」「真ん中の値」「4.2ポイント」「METR」「所得保障」も説明なしで出した。
- **(d) 主語・目的語・指示語を省かない。** 1行ごとに「誰が・何が・何を」が、その行と直前の行だけで分かるか確かめる。行頭の「それ・その・そこ・その間」は、何を指すかを1つに決められるときだけ使う。
  - 失敗: 「前提はこう」が誰の前提か分からなかった。「その間、入り口は〜」の「その間」が、何と何の間か分からなかった。
- **(e) 前の台詞に出ていない発言・事実・固有名詞を、知っている前提で出さない。** 引用するなら、先に「〇〇さんは、〜と言ってる」と紹介する。概要欄や資料カードにしか無いことを台詞で前提にしない。
  - 失敗: 「マスクさんの『小切手を配る』は〜」を、台詞では初めて出すのに、知っている前提で言った（概要欄にしか無かった）。
- **(f) たとえ話は、対応表（準備2）で原典と照合してから台詞にする。** 言葉はたとえと原典の間で統一する（同じものを別の言葉で呼ばない）。
  - 失敗: 「人を手伝う機械が増えれば、椅子の値打ちは上がる」と書いたが、原典の仕組みは「機械は人を手伝わない。作業どうしの補い合いで、自動化が進むと残る人手の作業が貴重になる」だった。さらに「機械」と「AI」が別物に聞こえて、「機械は必要？」と聞かれた。
- **(g) 書き手が3文で平易に説明できない仕組みは、台詞にしない。** 準備1のメモを書けないなら、資料を読み直すか、その論点を外す。
  - 失敗: 「全部終わる前に給料が崩れる」の理由を書き手が説明できないまま台詞にし、「意味がわからない」と言われた。
- **(h) 「資料に書いてあること」「二人の見立て」「資料の外の実感・仮定」を、台詞で区別する。** 資料の外の話は「資料には無い、できたらの話」と言う。二人の計算は「〜になる計算」「二人で概算した」と言う。
  - 失敗: 計算例（仮定を置いたモデル）の結果を「確かなのは、給料が減ること」と言い切った。
- **(i) 数字は、耳で追える丸め方にし、大きさの感覚を添える。** 1行に数字は3つまで。細かい値（31万4001円、1億2284万人）は「およそ31万円」「約1億2000万人」にする（正確な値はカードに任せる）。「何と比べて大きいか」を添える（2%＝月30万円なら6000円、年18%＝およそ4年で倍、50分の1＝5000円が100円）。換算の元（為替など）が確かめられない数字は、幅をもたせて言う（「日本円で十数万円」）。
  - 失敗: 「105日ごとに倍」「0.66%以下」「月31万4001円」が、大きいのか小さいのか分からなかった。
- **(j) 判定の札は2つ（構成 v4）。混ぜない、すり替えない。** 画面で大きく出す `verdict` は、二人が論点で育てた使い方（誰が・何に・どんな条件で）への札。小さく添える `claim_verdict` は、お題の主張（話者が言った時期・範囲のまま）への札。台詞では「発表の言い方には〇〇。でも、この使い方なら〇〇」のように、どちらの札かが分かるように言う。札が時期を言う場合（もうすぐ来る／3年はかかる）は、「この3年は、〜までの話」のように、何が・いつまでに、を台詞で言う。
  - 失敗: 大輔の「3年はかかる」が、お金が要らなくなるまでの3年なのか、食べ物が安くなるまでなのか分からなかった。
- **(m) 夢を潰して終わらない（構成 v4、2026-10-26）。** 問いは「本当か？」ではなく「どこまで来た？ どうすれば使える？」。誠実さ（資料の範囲を超えない、盛らない）は変えずに、資料を伝える順番と終わり方を変える。
  - 論点は「壁 → 越え方 → 残った手応え」の順で進め、**論点の最後の行は残った手応え**（tag `hope`）。限界・「まだ測っていない」は越え方の前に言い終える
  - 沙織は壁を出したら、越え方も一緒に探す。1話に1回は、沙織が「本物なら、私はこれに使いたい」と自分の使い道を言う（tag `skeptic_wish`）
  - 大輔も資料で勝つ。大輔の側を支える資料（第三者の評価・使った人の声・数字）で、沙織が認める論点を1つ以上作る（沙織の tag `turn`）
  - 大輔は削られても「狭める」「危ない」「無理」で引かない。「だったら、こう使う」と条件をつけて前に進む
  - 判定の後に、視聴者が今日・今月できる一歩を1つ言う（tag `next_step`。試す・設定を確かめる・待って何を見るか。投資判断・健康の助言にはしない）
  - 失敗（kl048）: 論点1は「毎日の暮らしで確かめた資料は、まだ無い」、論点3は「教え直しが効くかは、資料には無い」で終わり、大輔は「僕の使い道は、こう狭める」「僕の案、いきなり危ない」と夢を小さくした。大輔が正しかった論点でも、沙織が限界を2つ付けて終えた。同じ資料で、論点1は「控えめに出せば、8割の人が先回りを喜んだ。月に一度まとめて、なら今日から頼める」で終えられた。
- **(k) 初見の視聴者が自然に抱く疑問には、台詞で答えるか「資料に無い」と言う。** 疑問の例:「AIは、人間なら何時間の仕事を、どれくらいの確率でこなせるの？」「『高い収入』っていくら？」「なぜ比べる側にも50ドル渡すの？」「デンマークの研究なのに、なぜアメリカの研究所？」。理由が資料に無いことは、想像で補わない。
  - 失敗: 「半日の直し、もう届いてる」で、半日が何時間か、成功率がどうかを言っていなかった。
- **(l) 流れを見せる。** 論点の頭で「次に何を確かめるか」を言う。前の場面の最後で予告した話題から、それる場合は「〇〇の前に、一つ確かめたい」と言う。資料を出したら、その資料から分かったことを一言で残してから次へ行く（出してすぐ引っ込めない）。
  - 失敗: 「パンや家賃が次の論点」と言った直後に「その前に」で、お金の役割の話にそれた。デンマークの研究を出してすぐ「その通り」で引っ込め、何のために見せたのか分からなかった。

## 3. 書き終えたら、自分で確かめること（書き手のセルフチェック）
1. 準備4のキーワードを、すべて初出で定義したか
2. 判定の札が何を指すか（何が・いつまでに）を、台詞で言っているか
3. 誰の発言か・何の話か分からない文はないか（指示語を含めて）
4. 前に台詞で出ていない発言・固有名詞を、知っている前提で出していないか
5. 数字は耳で追えるか（1行3つまで、丸めたか、大きさの感覚を添えたか）
6. `python3 kl_dialogue.py check --episode kl{NNN}` の「読みやすさの手がかり」と v4 の ⚠ をすべて見て、直すか、直さない理由を書いたか
7. 見終わった視聴者に残るのは「削られた後の小さな夢」ではなく、「ここまで来ている。こうすれば使える」になっているか（各論点の最後の行と、判定・next_step だけを続けて読んで確かめる）

報告には、準備（`script_prep/kl{NNN}.md`）のパスと、上の7項目の結果を書く。
