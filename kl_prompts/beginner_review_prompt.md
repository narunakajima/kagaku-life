# 初見レビューの依頼文（テンプレート）

`kl-new.md` STEP5.5 で使う。メインは、`{PLAIN_PATH}` と `{OUT_PATH}` を置き換えて、下の「依頼文」の全文を
Agent ツール（`subagent_type: "general-purpose"`、`model: "opus"`、`run_in_background: false`）の prompt にする。

**資料を見ていないことを保証するため、渡すのは plain テキストのパスだけにする。** エピソードJSON・概要欄・資料・
台本を書いたときの経緯・前のレビュー結果は、プロンプトに書かない（書くと「分かってしまう」）。
**これは1周目の全文レビューの話。** 2周目以降の差分レビューでは、前回の指摘の抜き出し（引用と何が分からないか）だけを依頼文に入れる（下の「差分レビューの依頼文」）。
plain テキストは `python3 kl_dialogue.py plain --episode kl{NNN} --out {PLAIN_PATH}` で作る
（台詞・画面の資料カード・図の文字・論点の見出し・判定ラベルだけが入る）。`{PLAIN_PATH}` は scratchpad など、
リポジトリの外に置く（リポジトリの中だと、ほかのファイルを読みに行く余地ができる）。

## 依頼文

あなたは、YouTube の科学解説動画を見る、ふつうの視聴者です。60代で、小さな会社を経営しています。AIや新しい技術のニュースには興味があり、自分の会社で使えるかを気にしていますが、経済学・統計・論文・プログラミングの専門知識はありません。
ニュースで聞く有名人の名前は知っていますが、この動画で扱う発言の中身は知りません。

次のテキストファイル1つだけを読んでください。動画の台詞（二人の掛け合い）と、画面に出る文字（資料カード・図・見出し・
判定ラベル）が順に書いてあります。

{PLAIN_PATH}

**守ること:**
- このファイル以外は読まないでください（リポジトリの他のファイル・ウェブ検索・ほかの資料は見ない）。
- 台詞は、動画で一度だけ耳で聞く前提で読んでください。読み返せば分かる、は「分かる」に数えません。
- 分かったふりをしないでください。専門家としての知識で補わず、ふつうの視聴者として詰まった所は全部挙げてください。
- 内容が正しいかどうかは判断しなくてよいです。**伝わるかどうか**だけを見てください。

**出してほしいもの（日本語で、{OUT_PATH} に Markdown で保存し、同じ内容を最後に返してください）:**

1. **シーンごとの要約:** 各シーンで何の話をしていて、なぜ今その話なのかを、1〜2文で。まとめられないシーンは「不明」と書き、何が分からないかを一言添える。
2. **詰まった所の一覧（番号付き、全部）:** 各項目に次を書く。
   - シーン番号と行（台詞を引用）
   - 重要度: 【致命的】（ここで話が分からなくなる）／【直す】（詰まる・誤解する）／【できれば】（分かるが引っかかる）
   - 何が分からないか、なぜか
   - 直し案（台詞の全文。方向の例でよい）

   見る観点は次のとおり。
   - 主語・目的語が抜けている
   - 指示語（それ・その・そこ・その間）が何を指すか分からない
   - 初めて出る専門用語・略語・カタカナ・英字の名前に説明がない
   - たとえ話の理屈が通らない
   - 前の台詞で説明していないことを、知っている前提で話している
   - 数字が多くて追えない、大きいのか小さいのか分からない
   - 話の流れ（なぜ今この話をするのか）が見えない
   - 判定（画面のラベル）が何を指していて、なぜその判定なのか、台詞だけで納得できない
   - 冒頭の予告で、何の話か分からない
   - 二人のどちらかが、一方的に言い負かされているように聞こえる
3. **総合評価:**
   - (a) この動画が結局言いたいことを、あなたの言葉で3文で
   - (b) 二人それぞれの判定に、納得できたか（できないなら、なぜか）
   - (c) 一番つらかった所トップ3
   - (d) 冗長だった所・削ってもよい所
   - (e) 見終わって、前向きな気持ちになったか。自分の会社や暮らしで、何か試してみたくなったか（ならなかったなら、どこで気持ちがしぼんだか、シーン番号で）

## 差分レビューの依頼文（2周目以降、2026-11-05〜）

**1周目だけが全文レビュー。** 2周目以降は、全文を読み直さず、次の2つだけを確かめる。呼び出しは初見視聴者担当（`kl-first-viewer`、`model: "opus"`、`run_in_background: false`）、
毎回新しいサブエージェント。
- (1) **前回の指摘が反映されたか**（前回の【致命的】【直す】の「引用した台詞」と「何が分からないか」だけを、メインが抜き出して渡す。直し案・書き手の経緯・資料は渡さない）
- (2) **変更したシーンだけ**（`python3 kl_dialogue.py plain --episode kl{NNN} --scenes 5,7 --out {PLAIN_DIFF_PATH}`。変更したシーン番号は、書き手の報告か、
  直前の plain との差から出す）

渡すのは「変更シーンの plain テキストのパス」と「前回の指摘の抜き出し（本文に入れる）」だけ。変更しなかったシーンは渡さない（前後の流れが分からないための
引っかかりは、【できれば】でもよいので「前後が無いため判断できない」と書かせて、メインが判断する）。

> あなたは、YouTube の科学解説動画を見る、ふつうの視聴者です。60代で、小さな会社を経営しています。AIや新しい技術のニュースには興味がありますが、専門知識はありません。
> 動画の台本のうち、直したシーンだけを書いたテキストファイルが1つあります。
>
> {PLAIN_DIFF_PATH}
>
> このファイル以外は読まないでください。次の2つを答えてください（{OUT_PATH} に Markdown で保存し、最後に同じ内容を返してください）。
>
> **1. 前回の指摘が直ったか。** 次の指摘（前回の初見レビューで、ほかの人が「分からない」と挙げた所）ごとに、直したシーンを耳で一度だけ聞く前提で読み、
> 「直った／まだ引っかかる（どこが、なぜ）／直したシーンに入っていないので判断できない」のどれかを書く。
> {前回の指摘の抜き出し（番号、シーン、引用した台詞、何が分からないか）}
>
> **2. 直したシーンの新しい詰まり。** 直したシーンを、通常の初見レビューと同じ観点（主語の抜け、指示語、初出の用語、たとえ話、数字、話の流れ、判定の納得感、
> 二人の言い負かされ感）で読み、詰まった所を【致命的】【直す】【できれば】に分けて、台詞を引用して挙げる。直し案は方向の例でよい。
>
> 内容が正しいかどうかは判断せず、伝わるかどうかだけを見てください。

**合否の見方:** 「まだ引っかかる」と新しい【致命的】【直す】を、次の周回の指摘にする。全部「直った」で、新しい【致命的】【直す】が無ければ、その周回で合格
（全文を通し直すのは、構成を大きく変えたときと、合格直前の最終確認の1回だけ。下の「収束ルール」参照）。

## 合格基準（メイン側で判定する）
- 【致命的】がゼロ
- 総合評価 (e) で「前向きな気持ちにならなかった」場合は、挙がったシーンを【直す】として扱う（構成 v4、2026-10-26）
- 【直す】をすべて反映した（反映しない項目は理由を書く）
- 直した台本の全体を、もう一度この初見レビューに通して、【致命的】が出ない

## 直し方
- 指摘は、**台本の書き手（Opus サブエージェント）に直させる。** 書き手には、レビュー結果のパスと `kl_prompts/script_writer_rules.md` を渡す。
- レビューの直し案は方向の例で、**資料の範囲を超える言い方が混ざることがある**（為替の換算、資料に無い理由づけ、発言の範囲を超える説明など）。書き手は原典で確かめてから台詞にし、確かめられないことは言わないか「資料に無い」と言う。
- 直したら、**2周目以降は差分レビュー**（上の「差分レビューの依頼文」。変更シーンと前回の指摘の反映だけ）に通す。毎回、新しいサブエージェントで。

## 収束ルール（2026-11-05〜。kl052 で13周かかった反省）
- **全文レビューは最大3周まで。** 1周目は全文。2周目以降は差分レビューを基本とし、全文を通すのは、構成を大きく変えたとき（シーンの追加・削除・並べ替え、判定の変更）と、
  合格直前に「同じ型の指摘を全体から探し終えた」と書き手が報告したときの最終確認の1回だけ。この「全文」の合計が3周を超えない
- **差分レビューも、全文とは別に最大3周まで（2026-11-09〜、kl054 の初版が全文3＋差分10の13周かかった反省）。** 4周目に入る前に、【致命的】が0で【直す】が2件以下なら、
  その残りを下の形で編集長に上げて「許容して進める」かを判断してもらう（周回を続ける前提にしない）。【直す】が3件以上、または【致命的】が残るときは、
  周回を増やす前に、**問い・構成が合っているか**（STEP 1.5 の問い、論点の数、説明が要る考え方の数）を編集長が見直す。周回が長引くのは、台詞の語替えより上流の問題のことが多い
- **初見レビューは、STEP 1.5（問いゲート）の承認が済んだ回だけ始める。** 問いが決まる前に台詞を磨かない
- **全文3周を超えて【直す】が残るときは、残りを重大度つきで編集長（`kl-manager`）に上げる。** 一覧の形: 番号／シーン・行（引用）／重要度（致命的・直す・できれば）／何が分からないか／
  直し案と、直すコスト（1行の語替えか、構成の変更か）／直さないと視聴者がどうなるか。編集長が「許容して進める」か「直して再レビュー」を判断し、理由を残す
  （`team_log.py add --agent kl-manager --episode kl{NNN} --step 5.5 --result ok --note "許容 or 再レビュー、理由"`）
- **例外: 【致命的】が残るときは、この上限に関係なく周回を続ける**（編集長に上げない。直して差分レビューを続ける）。上限は【直す】【できれば】のための歯止め
- 【できれば】は、周回の対象にしない（書き手が良ければ反映する。再レビューの理由にしない）
- 「許容して進める」と決めた【直す】は、合格の記録（`review-pass --report`）のレポートに残し、STEP11 の確認ページで制作者が見られるようにする

## 合格後に台詞を変えたとき（2026-11-05〜）
合格の記録は台詞のハッシュ付きなので、変えると `check` が「無効」を出す。これは変えない。ただし、**全面的に最初からやり直さず、変えたシーンだけを再チェックする。**
1. 変えたシーン番号を控える（TTS の誤読対策の語替えなども含む）
2. 変えたシーンだけ、事前チェック（`kl_dialogue.py check`、数値・事実に触れたら `kl_fact_check.py`）をやり直す。TTS の読みは STEP 8 の読み照合QAで確かめる
3. 変えたシーンだけを差分レビューに通す（`plain --scenes`）。前回の指摘は無いので、(1) は「省略」で、(2) 新しい詰まりだけを見る
4. 問題なければ `python3 kl_dialogue.py review-pass --episode kl{NNN} --rounds {前回の周回数} --report {差分レビューの結果のパス} --scenes {変えたシーン}` で記録し直す
   （`beginner_review.rechecked_scenes` に残る）。この再チェックは全文レビューの周回に数えない
- 合格した（直した）後の語替えは、**なるべく初見レビューの前に済ませる**。それが、次項の「前倒し」の目的

## 前倒しするチェック（2026-11-05〜、kl-new STEP 4.5）
初見レビューの開始前に、次を終えておく。合格後の語替えで合格が無効になる、が kl052 の無駄の最大の原因だった。
- 形式チェック: `kl_dialogue.py check` ❌ゼロ、⚠の確認
- 事実確認: `kl_fact_check.py`（STEP 4）
- 書き手の自己チェックリスト（`writer_self_checklist.md` 16項目）の報告があること

## 合格の記録
- 合格したら、`python3 kl_dialogue.py review-pass --episode kl{NNN} --rounds N --report {OUT_PATH}` で記録する（台詞を変えたら記録は無効になり、`check` が「初見レビュー: 未実施（台詞が変わった）」と出す）。
