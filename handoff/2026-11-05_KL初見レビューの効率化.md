# KL初見レビューの効率化（2026-11-05）

## 背景
kl052 では初見レビューが13周しました。内訳を分析すると、(1) 合格後に TTS 誤読対策で台詞を変えたため合格が無効化され、再レビューが必要になった、(2) 全文レビューを繰り返すたびに新しい「直す」が出て収束が運次第になった、(3) 毎回全文を読み直していた、が主な無駄です（ユーザーとの相談で決定した改善策を実施するもの）。

## 依頼内容
KL の制作フロー（/kl-new の手順と、関係する担当者の定義）に、次の4点を反映してください。

1. **チェックの前倒し**: TTS の読み検査・事実確認・形式チェックを、初見レビューの開始前に完了させる順序にすること。あわせて、初見レビューの合格後に台詞を変更した場合は、合格を全面無効化せず、変更したシーンだけを再チェックする扱いにすること
2. **書き手の自己チェックリスト**: 過去の初見レビューの「直す」項目（kl052 の r1〜r13 を含む。記録は Desktop の scratch と team/work_log.jsonl にある）を集計してチェックリスト化し、書き手（ライアン）が台本の提出前に自己チェックする工程として組み込むこと。チェックリストの置き場所は実施側で判断し、結果ファイルに明記すること
3. **収束ルール**: 初見レビューの全文レビューは最大3周まで。3周を超えたら、残りの「直す」項目を重大度つきで kl-manager に上げ、管理担当が「許容して進める／直して再レビュー」を判断すること。致命的な項目がある場合は、この上限の例外として周回を続けること
4. **差分レビュー**: 初見レビューの2周目以降は、全文ではなく「前回の指摘が反映されたかの確認」と「変更されたシーンのみ」を対象にすること

## 結果報告
`handoff/results/2026-11-05_KL初見レビューの効率化.md` に、変更したファイルと箇所、チェックリストの置き場所と項目数、収束ルールの具体的な書き方を書いてください。
