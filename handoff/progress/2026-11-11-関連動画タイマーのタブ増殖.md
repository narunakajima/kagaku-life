# 関連動画タイマーが Studio のタブを開き続けた件（2026-11-11）

宛先: Muse。作成: Claude Code（KL セッション、なるさんの依頼）。

## 経緯
- なるさんが「`studio.youtube.com/video/V3JLr6_aKxU/edit`（kl055 のShorts）が Chrome でいくつも開かれている」と報告。
- 原因: KL の関連動画タイマー（`kl_related_auto.py`、iMac の launchd `com.naru.kl-related-auto`、15分間隔）が、同じ動画を約9.5時間開き直していた（state の `attempts: 38`）。
- 設定自体は済んでいた（実行ごとに `status: already`）。それでも毎回「失敗」と判定され、`related_video_set` が立たなかった。
- 失敗の原因: タイトルの食い違い。YouTube 側は「…（11月時点・定点観測 第1回）」、`episodes/kl055.json` の `youtube_title` は「…（11月時点）」。指示018で定点観測シリーズのタイトル表記を決めた際、YouTube 側だけ先に変わり JSON が追従していなかった。
- なお、実行が終わっても Studio のタブを閉じる処理が無く、さらに Claude in Chrome のタブ操作は実行（セッション）ごとにタブグループが別なので、後の実行は前の実行のタブを閉じられない。これがタブが溜まった理由。

## 対応（すべて push 済み）
KL（`kagaku-life`）
- `episodes/kl055.json`: `youtube_title` を YouTube 側に合わせ、`related_video_set: true` を記録。
- `kl_related_auto.py`:
  - タイトル照合で末尾の「（○月時点…）」を無視する（`_norm_title`）。
  - 3回続けて失敗した回は6時間空けて再試行（`FAIL_RETRY_HOURS`）。
  - 各実行が開いた Studio のタブを閉じる指示をプロンプトに追加。閉じた記録（`tabs_close_mcp`）が無い実行は、Slack に1回だけ通知（`check_tab_closed`）。
- `kl_title_check.py`（新規）: YouTube Data API で本編の実際のタイトルを取り、JSON と食い違えば Slack `#cc-reports` に通知。関連動画タイマーの冒頭から15分ごとに実行。`apply` で JSON を YouTube 側に合わせる（自動では書き換えない）。Shortsは対象外。
- `docs/series_humanoid.md`: シリーズ回の `youtube_title` は、アップロード前に「（○月時点・定点観測 第N回）」付きで JSON に入れる、と追記。
- なるさんがタイマーを一度止め、修正後に `kl_related_auto.py install` で再開済み。

SC（`samurai-chronicles`、`b8a491b`）・LW（`lamp-whisper`、`b3288b2`）
- 両タイマーは `tabs_close_mcp` を禁止していた（タブが残る作り）。SC・LW とも無限再試行は起きていない（SC は state が空・対象0件、LW は再試行間隔と上限あり）。
- なるさんの了承のうえ、`tabs_close_mcp` を許可し、各実行が開いた Studio のタブだけ閉じる指示を追加（SC: `sc_related_timer.py`、LW: `tools/lw-related-timer.sh`・`tools/lw-related-timer-prompt.md`）。他のタブと about:blank は閉じない。
- 最初の変更は自動判定に「セキュリティの弱体化」として拒否され、なるさんが許可して再実行した。
