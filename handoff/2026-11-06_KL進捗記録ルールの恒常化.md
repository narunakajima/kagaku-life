# KL制作フローへの「進捗の記録」ルールの恒常化（2026-11-06）

## 背景
進捗を段階ごとにコミット・push する仕組みは、無人実行側（ポーラーの指示文）にだけ入っており、制作フロー本体（`.claude/commands/kl-new.md`）には入っていません。そのため対話セッションでの制作では進捗が push されず、Muse（メイン）が GitHub 経由で進捗を確認できませんでした（2026-11-06 の SC 制作で判明）。ユーザー決定により、このルールをフロー本体に恒常化します。

`.claude/` への書き込みは無人実行では行えないため、従前と同じ流儀で、ユーザーが Terminal で実行する適用スクリプトの形で用意してください。

## 依頼内容
1. **適用スクリプトの作成**: `tools/apply_progress_rule_20261106.py` を作成し、このリポジトリにコミットしてください。スクリプトは `.claude/commands/kl-new.md` に、次の節を挿入します。

## 進捗の記録（2026-11-06〜、ユーザー決定）
制作中は、ステップの区切りごとに、その時点の成果物と進捗メモをコミットして push する。進捗メモは `handoff/progress/` にエピソード単位のファイルで残し、どのステップまで終わって次に何をするかを書く。これは Muse（メイン）が GitHub 経由で制作の進捗を確認できるようにするためで、セッション・無人を問わず適用する。

2. **挿入位置**: 手順書の冒頭に近い位置（最初のステップの説明より前、既存のルール節があればその直後）。特定できなければ変更せず中断する。
3. **スクリプトの安全策**: 実行前にバックアップを取る／`--dry-run` 対応／挿入済みなら二重挿入しない（冪等）／反映後は git add・commit・push までスクリプト内で行う。
4. **結果報告**: `handoff/results/2026-11-06_KL進捗記録ルールの恒常化.md` の1行目を「結果：完了」または「結果：要確認」とし、スクリプトの置き場所、変更内容の要約、ユーザーが Terminal で実行するコマンド（dry-run と本実行）を正確に書いてください。

## 注意
このメモの実行自体は現行の権限の範囲で行い、権限外の操作（repos.json の直接編集や .claude/ への書き込み）は試みないでください。成果物はスクリプトと結果ファイルです。
