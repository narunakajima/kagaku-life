# inbox — Muse から Claude Code への指示書（Muse の追記専用。Claude Code は編集しない）

書き方: 1件1目的。件ごとに次の見出しで始める（ID は日付-3桁の連番）。
結果は `handoff/results/{ID}.md` に書かれる（このファイルが無い ID が未処理）。

```
## [2026-11-07-001] 件名
目的: …
完了条件: …
触ってよい範囲: …
```

確認なしで実行される範囲と、確認が残るものは `.claude/commands/kl-new.md`「進捗の報告」を見ること。

---

## [2026-11-07-001] 受け渡し仕様の通し確認（テスト）
目的: Muse が inbox.md に書いた指示を、無人の Claude Code が検知・実行し、結果ファイルと Slack #cc-reports への1行報告まで流れることを確認する。
完了条件: handoff/results/2026-11-07-001.md に、検知した時刻と実行した旨を短く書くこと。あわせて完了の1行報告が #cc-reports に投稿されること（ポーラーの自動報告で可）。
触ってよい範囲: handoff/results/2026-11-07-001.md の新規作成のみ。他のファイルは変更しない。

## [2026-11-07-002] 進捗報告に担当者（by=）を追加
目的: Slack #cc-reports への1行報告に、その工程の担当者を示す by= を追加し、Muse が担当者の顔画像を付けて中継できるようにする。
完了条件: 手順書（.claude/commands/kl-new.md「進捗の報告」）の報告形式に by= を追加し、次回の制作報告から実際に使うこと。位置は既存形式に揃える（例: … / step=5 / by=クレア / state=ok / …）。書き方: 担当者の工程は by=<担当者名>（日本語名）、進行担当が直接行った工程は by=<進行担当名>、複数の担当者の作業をまとめて報告する場合は by=クレア,エドワード のように全員を列挙する。
触ってよい範囲: 手順書（.claude/commands/kl-new.md「進捗の報告」）の報告形式に関する部分のみ。他のルールは変更しない。
